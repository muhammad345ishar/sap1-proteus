Variable-Length SAP-1

In the 2-byte machine, OUT and HLT have no address byte, so fetching one wastes a memory byte and three clocks. The length signal LEN tells the 9-bit ring counter to jump from T3 straight to T7. One-byte instructions run 6 steps, two-byte instructions run 9, and not a single control equation changes.

Why LEN comes from the bus

The skip is decided at the end of T3, on the same clock edge that loads the opcode into IRH. IRH is still holding the previous opcode during T3, so LEN cannot be decoded from it. During T3 the memory is driving the opcode onto the W-bus (CE̅ is on), so the LEN gates read the bus.

After that edge the normal 8-bit decoder works from IRH, exactly as in the padded design. An alternative is one wait state after T3 and decoding from IRH, but that breaks the 6-step and 9-step counts.

Control equations stay the same. Ep = T1 + T4, Cp = T2 + T5, CE̅ = T3 + T6 + T8·MEM and the rest are unchanged. The ring simply never visits T4, T5, T6 for a one-byte instruction, so those terms are never true. LEN is used by the ring counter alone.

Cheaper encoding: if there are many short instructions, reserve one opcode bit as the length bit. Then LEN is that bit itself, with no decoding gates at all.

Extending the idea

3-byte machineD4 = T3·LEN̅
D10 = T9 + T3·LENJump from the end of the opcode byte to the first execute step T10.
4-byte machineD4 = T3·LEN̅
D13 = T12 + T3·LENSame pattern: skip lands on T3n+1.
More than two lengthsLEN1 LEN0Two length bits and a skip after each byte: after T3 jump if 1 byte, after T6 jump if 2 bytes, and so on.
Early resetD1 = T9 + T8·LDA + T7·OUTReturns the ring to T1 as soon as the instruction is done. With the skip, OUT drops from 6 steps to 4. Not used here because the spec asks for 6 and 9.

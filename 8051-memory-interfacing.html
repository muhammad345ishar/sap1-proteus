Digital Logic Design · Memory interfacing · Weeks 4–5

8051 Memory Interfacing

How a microcontroller switches on exactly one memory chip for every address. Every term is defined before it's used, every formula is derived, all the past-paper questions are solved step by step, and a machine at the end solves new ones for you.

The whole topic in one box

Can the class method do the past-paper chip-select questions? Yes, every one of them. The class method is four steps:

  1. Count the address lines (64K = 216, so 16 lines).
  2. Give each module its lower address lines (a 2m-byte module takes Am−1 … A0).
  3. Give the upper address lines to a decoder.
  4. Each decoder output is a chip select (CS).

The past papers add exactly one new idea: the modules have different sizes. So a big module covers several equal slices of memory (called blocks), and its CS is the OR of several decoder outputs. Everything else on this page is practice of that one idea.

If any word in that box is fuzzy, read the five prerequisites (P1–P5) in order. If it's all clear, jump to the Block Method.

Start here

The problem: many chips, one set of wires

The 8051 reads and writes memory by putting numbers on wires. It can address up to 64K bytes of external memory, but that memory often comes as several smaller chips, and all of them are connected to the same wires. This whole topic answers one question: when the 8051 puts out an address, how does the right chip, and only that chip, know it's being talked to?

Words you'll need

Bit, byte
A bit is a single 0 or 1. A byte is 8 bits.
IC (chip)
An integrated circuit: a package of circuitry with metal pins. The 8051 is an IC and so is each memory.
Memory location
One storage box inside a memory chip. It holds 1 byte.
Address
The number that names a location, like a house number on a street. Location 0, location 1, location 2, …
Address line, address bus
One wire per bit of the address, named A0, A1, A2, … A0 carries the least significant bit (LSB, the bit worth 1); the highest-numbered line carries the most significant bit (MSB). All the address wires together are the address bus.
Data bus
The 8 wires D7–D0 that carry the byte being read or written.
Read and write signals
~RD and ~WR: control wires from the 8051 that tell a memory whether to send out a byte (read) or store one (write). The bar on top means active-low.
Active-high, active-low
An active-high pin does its job when it is 1. An active-low pin does its job when it is 0. On a diagram, active-low pins get a small circle called a bubble.
Memory module
One memory chip with 2m locations. Its pins: m address pins, 8 data pins, ~RD, ~WR, and CS.
Chip select (CS)
The chip's on/off switch for the bus. When CS is active, the chip obeys ~RD/~WR. When CS is inactive, the chip ignores everything and its data pins go high-impedance.
High-impedance (tri-state)
An output state in which the pin behaves as if it were unplugged. This is what lets many chips share one data bus without interfering.
Logic gates
AND outputs 1 only if all its inputs are 1. OR outputs 1 if any input is 1. NOT (an inverter) flips 0↔1.
Address decoder
The logic circuit that looks at the address and makes exactly one CS active.
Memory map
A table or picture showing which range of addresses belongs to which chip (like the bar at the top of this page).

The rule everything follows

Every chip hangs on the same address bus and the same data bus. If two chips were selected for one address, both would push different bytes onto D7–D0 at the same moment. That is a bus conflict (also called bus contention): the byte the 8051 reads is garbage, and the fighting outputs can overheat.

Rule

For every address, at most one CS may be active. Exactly one if a chip lives at that address; zero if the address is a gap.

A picture to keep in your head

Think of the 64K address space as a building with 16 floors and 4096 rooms on each floor. An address like 8ABCh is a room number: the first hex digit (8) picks the floor, the last three digits (ABC) pick the room on that floor. The decoder is the lift operator: it opens the doors of exactly one floor. A small chip occupies one floor; a big chip occupies several floors, so its doors must open for any of them. That last sentence is the whole "OR gate" idea you'll meet later.

Prerequisite 1

Address lines and powers of 2

Each address line carries one bit. So the real question is: how many different addresses can n wires spell out?

WiresAll patternsCount
10, 12
200, 01, 10, 114
3000, 001, 010, 011, 100, 101, 110, 1118

Every time you add a wire, each old pattern appears twice: once with the new wire at 0 and once with it at 1. So the count doubles with every wire:

locations = 2 × 2 × … × 2 (n times) = 2n   ⟺   n = log2(locations)

log2 means "which power of 2 gives this number". log2 1024 = 10, because 210 = 1024.

Why 1K means 1024

Because sizes come from wires, memory sizes are always powers of 2. The power of 2 closest to 1000 is 210 = 1024, so in memory "1K" means 1024 bytes, not 1000. Then 2K = 211, 4K = 212, and so on: every doubling of size adds one line.

N K = N × 210.  If N = 2p, then N K = 2p+10 → p + 10 address lines.

Lines are counted from A0, so n lines are named An−1 … A0. A 64K system has 16 lines, A15 … A0; there is no A16 in it.

Example 1.1Sessional #1 2022, Q3(a)

A micro-controller has a code memory of 32K × 1 byte. How many address lines are needed to reach each location uniquely?

  1. Write 32 as a power of 2: 32 = 25.
  2. 32K = 25 × 210 = 215 locations.
  3. n = log2(215) = 15.

Answer: 15 lines, A14 … A0.

Example 1.2Sessional #2 2023, Q1(a)

A microcontroller can interface up to 128 KB. How many address lines are needed?

  1. 128 = 27, so 128K = 27 × 210 = 217.
  2. n = 17.

Answer: 17 lines, A16 … A0.

Example 1.3

How many address pins does an 8K memory chip have?

  1. 8 = 23, so 8K = 213 locations.
  2. To give each of its 213 cells its own number it needs 13 bits.

Answer: 13 pins, A12 … A0.

Example 1.4Reverse direction

A chip has 11 address pins. What is its size?

  1. 11 pins → 211 locations.
  2. 211 = 21 × 210 = 2 × 1K.

Answer: 2K.

Prerequisite 2

Hex, K-to-hex, and end addresses

Hexadecimal (hex) is base 16. It uses the digits 0–9 and then A = 10, B = 11, C = 12, D = 13, E = 14, F = 15. We write an "h" after a hex number (4000h) so it isn't mistaken for decimal.

Why addresses are written in hex

Four bits have 24 = 16 patterns, and hex has exactly 16 digits. So every hex digit is exactly 4 bits, which means exactly 4 address lines. (A group of 4 bits is called a nibble.)

Where "1K = 0400h" comes from

Hex place values go up by 16: 1, 16, 256, 4096. So 0100h = 256. Since 1024 = 4 × 256:

1K = 1024 = 4 × 256 = 4 × 0100h = 0400h
N K = N × 0400h = (4N) × 0100h

Multiplying by 0100h in hex just adds two zeros at the end, the same way ×100 does in decimal. That gives a shortcut you can do in your head.

Shortcut

To write N K in hex: multiply N by 4, convert that number to hex, then append 00.

Converting a number below 256 to hex: divide by 16. The quotient is the first hex digit and the remainder is the second. Example: 104 ÷ 16 = 6 remainder 8, so 104 = 68h.

End address = start + size − 1

A module with S locations that starts at address s uses s, s + 1, s + 2, …, up to s + (S − 1). Count them: that is exactly S numbers. So

end = start + size − 1 = (next start) − 1

Tiny check: a 4-location chip starting at 0 uses 0, 1, 2, 3. Its end is 3, not 4.

Subtracting 1 in hex: every trailing 0 becomes F, and the digit just before them goes down by 1. So 5000h − 1 = 4FFFh, and 7800h − 1 = 77FFh.

Prerequisite 3

The decoder

A decoder is a combinational circuit (its outputs depend only on its present inputs; it has no memory) that turns a binary number into "one wire out of many". Two ideas first.

Complement
~A (read "A bar" or "NOT A") is 1 when A is 0, and 0 when A is 1. It's what a NOT gate outputs.
Minterm
An AND of every input variable, each appearing exactly once, either plain or complemented. Example for inputs A1, A0: A1·~A0. A minterm is 1 for exactly one input combination.

Building the decoder from minterms

An AND gate gives 1 only when all its inputs are 1. Suppose we want a gate that fires only when A1A0 = 10. Feed it A1 (which is 1 exactly when A1 = 1) and ~A0 (which is 1 exactly when A0 = 0). So Y2 = A1·~A0.

Rule

For output Yi: write i in binary. Wherever the bit is 1, use the variable; wherever it is 0, use its complement. AND them together. That AND term is the minterm mi.

An n-to-2n decoder has n inputs and 2n outputs, with Yi = mi. The input can only be one number at a time, so exactly one output is 1: the one whose index equals the input number.

A1A0Y0Y1Y2Y3
001000
010100
100010
110001

Y0 = ~A1·~A0   Y1 = ~A1·A0   Y2 = A1·~A0   Y3 = A1·A0

The enable input

An enable is an extra input that switches the whole decoder on or off. With enable EN:

Yi = EN · mi

When EN = 0, every output is 0 no matter what the other inputs are. An active-low enable is written ~E and drawn with a bubble: the decoder works when that pin is 0. Inside, it is inverted once, so EN = NOT ~E.

Enables are what let you build big decoders from small ones. Two 2-to-4 decoders make a 3-to-8: A1, A0 go to both; A2 goes straight to the enable of the "upper" decoder and through a NOT gate to the "lower" one. When A2 = 0 only the lower decoder works and gives Y0–Y3; when A2 = 1 only the upper one works and gives Y4–Y7. The same trick lets one address line (A16 in the 2023 paper) switch a whole decoder off.

For reference: common decoder chips are the 74139 (two 2-to-4s), 74138 (3-to-8) and 74154 (4-to-16). Real ones have active-low outputs; in these exam questions, use active-high unless told otherwise.

Prerequisite 4

Splitting an address: which chip, which cell

This is where "a 2m-byte module takes Am−1 … A0" comes from.

The decimal version first

Take 4173 and divide by 100: 4173 = 41 × 100 + 73. Dividing by 100 just chops off the last two digits. The quotient, 41, says which hundred you're in. The remainder, 73, says where you are inside that hundred.

The binary version

Same thing with 2m instead of 100. Dividing a binary number by 2m chops off its lowest m bits (it shifts the number right by m places). So:

address = Q × 2m + R    Q = the top n − m bits,   R = the lowest m bits

Now cut the memory into equal slots of 2m bytes. Q tells you which slot the address is in, and R tells you which cell inside that slot. That's why:

  • A 2m-byte module needs m lines to name each of its 2m cells (P1), and they must be the lowest m lines, Am−1 … A0, because those are what change from cell to cell inside one slot.
  • The top n − m lines stay fixed across a whole slot, so they identify the slot. Feed them to a decoder and output YQ fires for every address in slot Q.

With 16K modules in a 64K space, where does 4ABCh go?

  1. 16K = 214, so m = 14: the module gets A13 … A0, the decoder gets A15 A14.

  3. Low 14 bits: 00 1010 1011 1100 = 0ABCh.

Example 4.2

With 8K modules, where does C123h go?

  1. 8K = 213, m = 13. Decoder gets the top 3 lines A15 A14 A13.
  2. C = 1100, so the top three bits are 110 = 6 → Y6 (the 7th module).
  3. Cell = C123h − 6 × 2000h = C123h − C000h = 0123h.

Example 4.3

With 4K slots, where does 7F00h go?

  1. 4K = 212, m = 12. Decoder gets A15–A12, which is exactly the first hex digit.
  2. First digit 7 → slot 7. The other three digits, F00h, are the cell.

Answer: slot 7, cell F00h. With 4K slots you can read the slot number straight off the first hex digit, which is why 4K blocks show up so often in past papers.

Prerequisite 5

Merging decoder outputs

The OR gate is all you need

If a module owns blocks 4, 5, 6 and 7, its CS must be 1 whenever the address is in any of them:

CS = Y4 + Y5 + Y6 + Y7  (+ means OR)

Only one Y is ever 1, so this means exactly "the address is somewhere in my blocks". This is always a full-marks answer. Everything below is optional shortening.

Optional: shortening the equation

Each Y is a minterm, so an OR of Ys can be simplified with Boolean algebra. This is the same grouping you do on a K-map (Karnaugh map: the grid where you circle 1s in pairs, quads and octets). The one identity behind all of it:

X·A + X·~A = X·(A + ~A) = X·1 = X

Two minterms that differ in only one variable merge into one term, and that variable disappears. A pair drops 1 variable, a quad drops 2, an octet drops 3.

Example 5.1Derivation of a quad

Simplify Y4 + Y5 + Y6 + Y7 for a 4-to-16 decoder on A15 A14 A13 A12.

  1. Blocks 4–7 in binary: 0100, 0101, 0110, 0111. The top two bits are always 01.
  2. Factor out the common part: ~A15A14·(~A13~A12 + ~A13A12 + A13~A12 + A13A12).
  3. The bracket lists all four combinations of A13, A12, so it is always 1.

Answer: Y4 + Y5 + Y6 + Y7 = ~A15A14.

The aligned-group test

In a run of 2j consecutive block numbers that starts at a multiple of 2j, the lowest j bits go through every pattern from 00…0 to 11…1 while the higher bits stay fixed. So the lowest j variables drop out and the whole run becomes one AND term. If the run starts anywhere else, the higher bits change partway through, and it won't collapse into one term.

Blocks (4K, lines A15A14A13A12)Aligned?CS
4,5,6,7 = 0100–0111yes: 4 is a multiple of 4 → quad~A15A14 (drop A13, A12)
10,11 = 1010, 1011yes: 10 is a multiple of 2 → pairA15~A14A13 (drop A12)
13,14 = 1101, 1110no: 13 is oddtwo terms: Y13 + Y14

Look at why 13, 14 fail: as a pair, their top three bits are 110 and 111, which differ. So no single variable can be dropped.

The XOR shortcut (it appears in two papers)

XOR (exclusive OR), written A ⊕ B, is 1 when exactly one of A, B is 1. Truth table: 00 → 0, 01 → 1, 10 → 1, 11 → 0. Writing an AND term for each row that gives 1:

A ^ B = ~A·B + A·~B
Example 5.2Sessional #1 2022

On A14 A13 A12 A11, simplify Y4 + … + Y11.

  1. Blocks 4–7 = 01xx (aligned quad) → ~A14A13.
  2. Blocks 8–11 = 10xx (aligned quad) → A14~A13.
  3. Sum: ~A14A13 + A14~A13, which is the XOR formula.

Answer: A14 ^ A13: "exactly one of A14, A13 is 1".

Example 5.3Sessional #1 2022

Simplify Y13 + Y14 on A14 A13 A12 A11.

  1. 13 = 1101 → A14A13~A12A11; 14 = 1110 → A14A13A12~A11.
  2. Factor out A14A13: A14A13(~A12A11 + A12~A11).
  3. The bracket is the XOR formula.

If the CS pin is active-low

De Morgan's theorem says NOT(X + Y) = ~X · ~Y. So:

  • Active-high decoder outputs + active-low CS: OR, then NOT. That's one NOR gate.
  • Active-low decoder outputs (~Ya, ~Yb) + active-low CS: ~CS = ~Ya · ~Yb, an AND gate.

The questions on this page say active-high or give no polarity, so we use active-high throughout.

The method, part 1

The class method: equal modules

  1. Total address lines n (64K → n = 16).
  2. Module size 2m → lines Am−1 … A0 go to every module, together with ~RD, ~WR and D7–D0.
  3. The remaining top n − m lines go to a decoder.
  4. Decoder output Yi = CS of module i.

Where the decoder size comes from: n lines in total, m of them are used inside each module, so the rest choose the module:

k = n − m decoder inputs  →  a k-to-2k decoder, one output per module

The method, part 3

The Block Method: one recipe for every question

Idea

Cut the whole memory into equal blocks of size B, chosen so that every module is made of a whole number of blocks. Then decode the blocks:

one block = one decoder output  ⟹  CS of a module = OR of the outputs of its blocks

Why B must divide every start address and every size

If it does, every module boundary lands exactly on a block boundary. Then each block is either entirely inside one module or entirely empty, and each decoder output can be handed to exactly one module (or to nobody).

If it doesn't, a block straddles a boundary. Example from the 2022 sessional: M2 starts at 6K = 1800h. With 4K blocks, block 1 would be 1000h–1FFFh: half gap (1000h–17FFh), half M2 (1800h–1FFFh). Connecting Y1 to M2 would wrongly select M2 for the gap too.

Why the largest such B

Any smaller power of 2 also divides everything, so it also works, but it cuts memory into more blocks and needs a bigger decoder. The largest B gives the smallest decoder.

Why the decoder gets the top k lines

Block number = address ÷ B. B = 2b, and dividing by 2b chops off the lowest b bits (P4). What's left is the top n − b lines. So:

k = n − log2 B decoder inputs, and decoder output index = block number

Why each module still gets its own m lines

The decoder only answers "is this address inside M2?". M2's own lines answer "which of M2's cells?". A 16K module covering four 4K blocks needs all 14 of its lines A13 … A0; with only 12, its four blocks would land on the same 4K of cells.

The 7 steps

  1. Address lines. Total memory = 2n → lines An−1 … A0.
  2. Table. For every module: size, start, end (decimal → hex), and lines inside (2m → m lines).
  3. Block size B. The largest power of 2 that divides every start address and every size (often the smallest module). Decoder inputs: the top k = n − log2 B lines. Enable trick: if every module has the same value on the top line (2023 paper: A16 = 0 everywhere), feed that line to the decoder's enable instead and use one fewer input.
  4. Block numbers. Block of an address = address ÷ B. A module covers blocks start ÷ B up to (end + 1) ÷ B − 1.
  5. Chip selects. CSi = OR of the decoder outputs of module i's blocks (one block: just a wire). Check that no block belongs to two modules.
  6. Draw. Lower lines → each module; ~RD, ~WR, D7–D0 → every module; top k lines → decoder; decoder/OR outputs → CS pins. Unused outputs stay unconnected.
  7. Verify. Test the start, the end, and the address just after the end of each module.

Finding B fast

Write every start and size in K. For each one, find the biggest power of 2 that divides it (skip 0, since 0 is divisible by everything). The smallest of those is B.

Example 7.1Sessional #1 2022

Starts 0, 6, 8, 26 and sizes 2, 2, 16, 4 (all in K). Find B.

  1. Starts: 6 = 2 × 3 → 2; 8 → 8; 26 = 2 × 13 → 2.
  2. Sizes: 2 → 2; 2 → 2; 16 → 16; 4 → 4.
  3. Smallest: 2.

Answer: B = 2K = 211. With 15 lines, k = 15 − 11 = 4: a 4-to-16 decoder on A14 A13 A12 A11.

Sessional #1 · 9 Nov 2021 · Q3 · 14 marks

Three modules in 64K

A micro-controller has a 64 KB address space. Interface three memory modules, one of 8 KB and two of 4 KB, so that they occupy the address ranges 0 to 8K − 1, 16K to 20K − 1 and 32K to 36K − 1. Each module has an active-HIGH chip-select pin. Draw the interfacing circuit using a decoder.

Step 164K = 216 → 16 lines, A15 … A0.

Step 2Convert every boundary with N K = (4N in hex)00: 8K = 2000h, 16K = 4000h, 20K = 5000h, 32K = 8000h, 36K = 9000h. End = next start − 1.

Step 3Starts 16, 32 and sizes 8, 4, 4 (in K). Biggest power of 2 dividing each: 16 → 16, 32 → 32, 8 → 8, 4 → 4, 4 → 4. Smallest: 4, so B = 4K = 212. k = 16 − 12 = 4 → a 4-to-16 decoder on A15 A14 A13 A12.

Step 4With 4K blocks, the block number is just the first hex digit (P4). M1: 0000h–1FFFh → blocks 0, 1. M2: 4000h–4FFFh → block 4. M3: 8000h–8FFFh → block 8.

Step 5CS1 = Y0 + Y1,   CS2 = Y4,   CS3 = Y8. No block appears twice. ✓

Step 6

Not drawn: each module's lower lines (as labelled), D7–D0, ~RD, ~WR go to every module. Grey stubs are unconnected outputs.

Shorter forms (optional)

Y0 + Y1 are blocks 0000 and 0001: an aligned pair, so A12 drops: CS1 = ~A15~A14~A13. Then CS2 = ~A15A14~A13~A12 and CS3 = A15~A14~A13~A12, so the circuit also works with only AND gates and inverters.

The book's version: the same method with bigger blocks

The solution file used a 3-to-8 decoder on A15A14A13 (8K blocks). Then Y0 = 0000h–1FFFh is exactly M1. But Y2 (4000h–5FFFh) and Y4 (8000h–9FFFh) are 8K, while M2 and M3 are only 4K. Each sits in the lower half of its slice, where A12 = 0, so the book patches it: CS2 = Y2·~A12, CS3 = Y4·~A12. Both versions are correct. The patch is needed because 8K doesn't divide the 4K sizes; the Block Method's choice of B avoids it.

Final answer

A12 … A0 → M1; A11 … A0 → M2 and M3; A15A14A13A12 → 4-to-16 decoder.

CS1 = Y0 + Y1 (0000h–1FFFh), CS2 = Y4 (4000h–4FFFh), CS3 = Y8 (8000h–8FFFh).

      The 2K trap

      A micro-controller has a code memory space of 32K × 1 byte.

      (a) How many address lines are needed to access each of the 32 KB locations uniquely?

      (b) Interface these modules at the given addresses and propose the address-line scheme with block diagrams: 2K at 0 to 2K − 1; 2K at 6K to 8K − 1; 16K at 8K to 24K − 1; 4K at 26K to 30K − 1.

      (a)32K = 25 · 210 = 215 → 15 address lines, A14 … A0 (Example 1.1).

      Step 22K = 0800h, 6K = 1800h, 8K = 2000h, 24K = 6000h, 26K = 6800h, 30K = 7800h.

      Step 3 · the trapStarts 6 and 26 are not multiples of 4: 6 → 2, 26 → 2. So 4K blocks don't work, and B = 2K = 211. k = 15 − 11 = 4 → 4-to-16 decoder on A14A13A12A11.

      Step 4Block = address ÷ 2K. Since 2K = 0800h, blocks start at 0000h, 0800h, 1000h, 1800h, … M1: 0 ÷ 2 = 0. M2: 6 ÷ 2 = 3. M3: 8 ÷ 2 = 4 up to 24 ÷ 2 − 1 = 11. M4: 26 ÷ 2 = 13 up to 30 ÷ 2 − 1 = 14. Blocks 1, 2, 12, 15 are unused.

      Step 5CS1 = Y0,   CS2 = Y3,   CS3 = Y4 + Y5 + … + Y11,   CS4 = Y13 + Y14

      Step 6

      Not drawn: each module's lower lines, D7–D0, ~RD, ~WR go to every module.

      Shorter forms (optional): the book's equations and where they come from

      Blocks 4–7 = 01xx and 8–11 = 10xx are two aligned quads: ~A14A13 + A14~A13, so CS3 = A14 ^ A13 (Example 5.2). Blocks 13 = 1101 and 14 = 1110 are not an aligned pair, so CS4 = A14A13~A12A11 + A14A13A12~A11 = A14A13(A12 ^ A11) (Example 5.3). Also CS1 = ~A14~A13~A12~A11 and CS2 = ~A14~A13A12A11.

      Heads-up: modules that start "off-grid"

      M3 is 16K but starts at 8K, and M4 is 4K but starts at 26K. Neither start is a multiple of its own size. M3 uses A13 … A0, so address 2000h reaches its internal cell 2000h and 4000h reaches cell 0000h. M4 uses A11 … A0: 6800h reaches cell 800h and 7000h reaches cell 000h. Every address still hits a different cell, so the design is correct; the data are just stored "rotated". The exam doesn't ask about this.

      Final answer

      (a) 15 lines. (b) CS1 = Y0,   CS2 = Y3,   CS3 = Y4 + … + Y11 = A14 ^ A13,   CS4 = Y13 + Y14 = A14A13(A12 ^ A11).

      Lines inside: 11, 11, 14, 12. Blocks 1, 2, 12, 15 select nothing.

        128K space, A16 as enable

        A microcontroller can interface up to 128 KB of memory. Modules: 8K at 0 to 8K − 1; 16K at 8K to 24K − 1; 32K at 24K to 56K − 1; 4K at 56K to 60K − 1; 4K at 60K to 64K − 1.

        (a) How many address lines are needed for the complete memory space? (b) Draw the interfacing block diagram showing the address-decoding scheme, with all inputs, outputs and signals.

        (a)128K = 27 · 210 = 217 → 17 lines, A16 … A0.

        Step 217 lines → 5 hex digits. 8K = 02000h, 24K = 06000h, 56K = 0E000h, 60K = 0F000h, 64K = 10000h.

        Step 3Starts: 8 → 8, 24 = 8 × 3 → 8, 56 = 8 × 7 → 8, 60 = 4 × 15 → 4. Sizes: 8, 16, 32, 4, 4. Smallest: 4 → B = 4K = 212. That gives k = 17 − 12 = 5, a 5-to-32 decoder. But every module ends by 64K − 1 = 0FFFFh, so A16 = 0 for every module. Enable trick: use a 4-to-16 decoder on A15A14A13A12 and connect A16 to its active-low enable. When A16 = 1 (the upper 64K), the decoder is off and nothing is selected.

        Step 4Block = the first hex digit after the leading 0. M1 → 0, 1. M2 → 2 to 5. M3 → 6 to 13 (6h … Dh). M4 → 14 (Eh). M5 → 15 (Fh).

        Step 5CS1 = Y0 + Y1,   CS2 = Y2 + … + Y5,   CS3 = Y6 + … + Y13,   CS4 = Y14,   CS5 = Y15. All of them already include ~A16, because the decoder is enabled only when A16 = 0.

        Step 6

        The bubble on E means active-low: the decoder runs only when A16 = 0. Not drawn: lower lines, D7–D0, ~RD, ~WR to every module.

        Shorter forms (optional): the book's equations, each also containing ~A16

        • CS1: blocks 0, 1 = 000x, an aligned pair → ~A15~A14~A13.
        • CS2: blocks 2–5 = 0010, 0011, 0100, 0101 → pairs 001x and 010x → ~A15~A14A13 + ~A15A14~A13 = ~A15(A14 ^ A13).

        • CS4 = A15A14A13~A12,  CS5 = A15A14A13A12.

        (a) 17 lines. (b) 4-to-16 decoder on A15 … A12, active-low enable = A16.

          Reference

          Exam cheat sheet

          One-page summary
          1. n = log2(memory size). A 2m module uses Am−1 … A0.
          2. Table: size, start, end (hex). End = next start − 1. 1K = 0400h, and N K = (4N in hex) followed by 00.
          3. B = largest power of 2 dividing all starts and sizes. Decoder on the top k = n − log2 B lines. If the top line is the same for every module, make it the enable.
          4. Blocks: start ÷ B up to (end + 1) ÷ B − 1.
          5. CSi = OR of the module's decoder outputs. Optional: merge aligned groups (pair drops 1 line, quad drops 2, octet drops 3).
          6. Draw: lower lines + ~RD + ~WR + D7–D0 to every module; top lines to the decoder; unused outputs unconnected.
          7. Verify start, end, and the address after the end.

          Common mistakes

          • Choosing a block size larger than a module, or one that doesn't divide a start address (the 2022 question: 6K and 26K need 2K blocks).
          • Forgetting that end = start + size − 1 (4FFFh, not 5000h).
          • Sending the top lines to the modules, or the lower lines to the decoder. A module takes only its own m lines.
          • Forgetting ~RD and ~WR on every module.
          • Giving one block to two modules: their CS would be active together (bus conflict).
          • Writing 1K = 1000 instead of 1024 = 0400h.
          • In a 128K question: forgetting that A16 = 1 must switch everything off.

          What to write in the exam

          Draw the decoder + OR gates diagram (safe, class style), write the table with hex ranges, and give the CS equations. Add the shortcut form if you have time.
